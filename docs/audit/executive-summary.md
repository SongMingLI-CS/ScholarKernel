## 5. 原任务十个最终问题

### 1）当前真实水平

有实际代码和工程整合能力的中等规模原型，具备研究应用方向的扩展基础；尚不是稳定生产系统或效果经过验证的学术 AI 平台。其不足主要是关键环节没有形成正确性闭环，而不是功能数量少。

### 2）是否达到 AI/LLM 实习项目面试标准

可以用于介绍原型和暴露学习过程；**尚未达到“高质量主项目、可承受深入追问”的目标**。LLM 应用工程岗位：完成 P0、核心状态/证据修复和一套小型可信评测后，有望成为有竞争力的项目。ML/DL 算法岗位：还需要独立 Python/PyTorch 训练、数据与实验，不可用 API 调用替代。个人能力仍需现场代码/原理考核。

### 3）最有价值的三个亮点

多模型 SDK/代理与流式 UI 的工程接入；真实并行评审与顺序聚合的可观察工作流；搜索来源、文档编辑及 PostgreSQL 持久化的应用闭环基础。亮点是已有工程实现，优越性尚无效果实验。

### 4）最大的五个缺陷或证据缺口

数据/文件权限边界；PDF 正确性；迁移一致性；运行状态与恢复/人工干预闭环；独立 AI/RAG 评测与成本记录缺失。前五优先修复任务则更具体地拆为文件边界、消息归属、PDF、迁移、人工干预授权。

### 5）哪些是集成，哪些体现 AI 深度

SDK、多供应商、Prompt 角色、外部 BGE/Cohere 接入主要是工程集成；检索/切片规则可以体现算法理解，但不等于训练。真正 AI 深度来自可解释的检索/排序实现、可信标注、误差分析、公平消融、训练损失/负样本和质量-成本曲线；当前这些证据不足。

### 6）哪些模块的面试收益最大

Executor 状态/取消/恢复，RAG 来源与解析，独立评测/预算，Prisma 迁移与隔离。把一两个链路亲自实现并完成失败案例，比增加供应商、角色和 UI 更有收益。

### 7）是否值得继续投入

值得。已有前端、模型和存储基础可以保留，问题多数有明确位置。建议有范围地修正，不重新造完整平台；研究训练另建仓库，使应用成为模型结果的展示端。若求职偏算法，把学习和实验时间从 UI 扩展转向独立研究。

### 8）哪些代码必须本人理解或重写

必须亲自理解分流/计划验证、节点执行状态与取消、Promise.all/检查点、所有权查询/事务/迁移、PDF→chunk→引用链、BM25/rerank、指标与实验配置。选择执行状态机、全库 BM25/指标计算和一个最小 PyTorch 训练循环亲手实现，不要求把整个项目从头重写。

### 9）如何形成可信量化成果

固定 commit、环境、数据哈希、模型版本、预算、标注和评价标准；保留逐案例原始结果和失败原因；分别报告路由、任务完成、基础设施成功、检索质量、引用支持、延迟及真实用量。做多次配对实验和人工复核，未知项明确 unknown。只有这些结果实际产生后，才写英文简历的提升数字。

### 10）下一阶段实施顺序

第一轮：文件读取边界与消息所有权的防御性修复和合成数据回归；第二轮：有界 PDF 解析与明确错误；第三轮：补迁移、人工干预授权；第四轮：统一权威执行路径、状态/错误/检查点与可达恢复；第五轮：来源 ID、预算和独立评测；最后才做 Python Reranker 接入/训练。
