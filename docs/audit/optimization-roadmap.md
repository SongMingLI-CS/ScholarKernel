# ScholarKernel 分阶段优化路线

基线：`e129eb65e6bcbf6c2df9696c282613a557b672f1`。本轮只交付审计与计划，没有实施以下业务修改。安全事项仅依据已有证据整理为防御性工作，不继续攻击模拟；受安全策略限制，未进一步验证。

工作量按一名熟悉本仓库的开发者、每天约 5-6 小时有效工作、AI 辅助且无生产数据迁移估计。负责人边学边做、真实论文标注、供应商接入及环境排障会显著增加时间；估计不是承诺。依赖未就绪时不把等待记成开发效率问题。

## P0：先恢复可信的基本边界和运行能力

### 1. 关闭通用文件暴露并约束读取根目录

- **问题/证据**：F01/F18；`api/source/route.ts:7-36` 无鉴权/文件白名单，真实登录开启后匿名合成隐藏文件仍可读；`file-reader-server.ts:56-58` 未限制父目录。已有日志完整保留。
- **修改位置**：source API、file-reader-server、FileTool 的权限注入及 middleware/服务器统一鉴权。
- **实施**：明确是否需要公开源码读取；不需要则关闭。需要则只允许专用数据/源码目录，检查真实路径、文件类型和大小，在工具层也执行同一策略；禁止依赖 Prompt 保护文件边界。
- **难度/工作量**：中，1-2 人日；若需多平台符号链接策略增加约 1 日。
- **收益**：消除已确认的文件暴露条件，降低错误工具调用影响面。
- **验收**：普通功能允许的合成文件可读；匿名/非授权文件拒绝；目录外和未知类型拒绝；不使用真实敏感文件验证。
- **面试价值**：能解释最小权限、API 与工具双层约束、为什么正则 path 检查不足。

### 2. 修复消息更新的对象归属条件

- **问题/证据**：F02；`conversations/[id]/messages/route.ts:24-49` 只检查目标会话，却按全局消息 ID 更新。真实本地 PostgreSQL 已确认跨用户合成消息被覆盖。
- **修改位置**：消息 POST、相关 route 测试，必要时数据库约束/消息 ID 契约。
- **实施**：已存在消息必须同时属于当前用户的目标会话；不匹配返回 404/409。保留事务，明确客户端幂等 ID 的碰撞处理。
- **难度/工作量**：低至中，0.5-1.5 人日。
- **收益**：恢复基本租户隔离。
- **验收**：两个合成租户，目标会话和消息组合矩阵；错归属不修改数据；同一会话重复提交仍正确；真实测试库执行。
- **面试价值**：区分认证、授权、唯一键和事务，能讲清安全查询条件。

### 3. 更换/隔离 PDF 解析并保留明确失败状态

- **问题/证据**：F03/F07；`pdf-text-extract.ts:84-109` 索引循环；`:55-71` 未解压 FlateDecode；593 字节未压缩样例超时、622 字节压缩样例空文本。解析 API 未鉴权，CPU 工作没有进程级限制。
- **修改位置**：pdf-text-extract、layout-aware-parser、documents/parse、browser-file 及解析契约。
- **实施**：先设置有界解析执行与错误状态，移除确定性循环；再选健壮 PDF 解析实现或接独立服务。明确 supported/unsupported/empty/timeout，前端显示警告。不要扩展为自行实现完整 PDF 标准。
- **难度/工作量**：中至高，3-5 人日；真实双栏/公式质量优化另需语料与 3-7 日，不在基础修复承诺内。
- **收益**：核心上传可终止、失败可解释；避免错误文本进入后续 AI。
- **验收**：已有两样例有界结束；压缩、字体、单双栏及扫描样例分别有预期；真实小语料记录正文/页码/顺序误差；资源上限测试只在受控环境。
- **面试价值**：输入解析可靠性、同步 CPU 与事件循环、降级设计和数据质量意识。

### 4. 补齐数据库迁移与空库部署门禁

- **问题/证据**：F04；schema 的 UserBilling/TokenAuditLog 无迁移，migrate 返回 0 后 diff 返回 2；真实登录计费接口 500/P2021。
- **修改位置**：新增 Prisma migration、CI、部署文档和就绪检查。
- **实施**：新增向前迁移，不改写已应用历史；CI 用空库 migrate deploy + schema diff；保留 db push 作为开发命令，不用它替代生产迁移验收。
- **难度/工作量**：中，1-2 人日；若生产已有非一致 schema，需先只读检查并另估数据迁移。
- **收益**：消除新部署缺表，建立配置/schema 可追溯性。
- **验收**：PostgreSQL 16 空库从迁移重建，diff 无差异；登录后设置、会话和计费可用；重复部署无破坏。Docker daemon 可用时再验容器，不假记通过。
- **面试价值**：讲清 CI 与生产路径差异、迁移演化及部署证据。

### 5. 先校验人工干预所有权，再统一运行域

- **问题/证据**：F05/F12；`intervention/route.ts:61-68` 先 resolve 后校验；browser executor 与 server Gate 分离；默认总暂停。
- **修改位置**：human-intervention-gate、intervention API、use-chat-send、human-intervention-panel、server-run/Job API。
- **实施**：P0 部分绑定 user/job/node，先验证再改变任务，停止接受任意客户端拓扑；随后在 P1 统一实际等待与提交的运行域，加入等待期限、取消及可恢复状态。
- **难度/工作量**：中；P0 授权修复 1-2 人日，完整 UI/服务端闭环另外 2-4 人日，计入后续执行一致性任务避免重复相加。
- **收益**：干预不会误作用，产品按钮能对应真实运行。
- **验收**：所有权失败无副作用；正确用户批准/redirect 真正影响同一运行后续；一致意见的暂停策略明确；无 session/取消/超时有结果。
- **面试价值**：Human-in-the-Loop 的控制流、状态与授权，比“有干预面板”更有说服力。

### 6. 收敛认证配置、敏感日志和依赖风险

- **问题/证据**：F15/F16/F20；Tavily 请求日志含 api_key；认证仅按 AUTH_PASSWORD 开启；production 无 proxy token 放行；npm audit 有依赖告警。
- **修改位置**：session-auth、auth-user、proxy-client/gateway、search-tool、统一日志模块、依赖锁与部署配置。
- **实施**：明确单用户/多用户模式和 OAuth 开关；应用访问 Token 与上游 Key 分离；日志默认不记录请求体/原文/Key；按官方公告和实际使用功能分类依赖风险再升级。
- **难度/工作量**：中，1-3 人日，依赖大版本不兼容另估；不盲目 force fix。
- **收益**：部署行为与文档一致，避免开启真实 Key 后泄露日志。
- **验收**：合成 Key 脱敏、认证配置矩阵、匿名保护行为；升级后原有门禁和普通业务回归，不开展新的渗透测试。
- **面试价值**：配置治理、威胁边界和供应链风险判断；不以告警数夸大安全能力。

## P1：面试价值最高的可靠性与评测

### 7. 建立 run/step 状态真值与可达恢复

- **证据/修改位置**：F06/F09/F10/F12/F13；Executor.run、llm-utils、Job API、agent-jobs、peer-review-runner 和聊天入口。
- **任务**：统一实际执行入口和计量依赖；返回 done/partial/failed/cancelled；更新内存与返回节点；错误流传播；每审稿分支完成即写检查点；排队/带版本持久化；提供恢复旧 Job 的最小入口。
- **难度/工作量**：高，4-7 人日，包含第 5 项的运行域闭环；先单进程，不要求队列平台迁移。
- **收益**：失败不会伪装成功，任务可解释、可测和可继续。
- **验收**：成功/部分失败/取消/超时/人工等待/重新加载均有明确状态；旧 Job 不重复已完成步骤；控制写入顺序；一条完整浏览器流程和一条重启恢复证据。
- **面试价值**：并发、异常、持久化与幂等的完整工程故事。

### 8. 修复 RAG 证据契约与检索真实性

- **证据/修改位置**：F07/F08/F14；chunker、column-reorder、browser-file、search strategy、rerank gateway、reasoning/context。
- **任务**：未知页码保留 unknown；无布局证据不重排；上传保留 stable doc/chunk/page/offset；引用全局 ID 一致；控制 chunk 长度和 query 相关选取；统一服务端重排、超时、结果校验；保留候选与来源快照。
- **难度/工作量**：中至高，3-6 人日，不包括大规模人工标注/训练。
- **收益**：来源可回溯，检索与生成错误可定位。
- **验收**：人工检查的 PDF/引用小集；无证据不伪造页码；多次搜索引用不串号；外部重排不可用时有界降级；真实来源支持关系逐条抽查。
- **面试价值**：能讲出 RAG 每层误差与取舍，避免只会调用向量库。

### 9. 建立独立评测与可信预算/成本

- **证据/修改位置**：历史 batch 脚本、llm-utils:70、billing bridge/pricing、Agent/RAG 评测脚本与数据目录。
- **任务**：冻结独立路由标签与任务 rubric；尊重总 Token 预算；记录全部调用（含 rewrite/重试/工具）、搜索次数、价格版本；离线 Recall/MRR/nDCG；小规模 A/B/C 评审消融。
- **难度/工作量**：中至高，4-7 人日工程 + 标注/模型费用/实验等待另计。
- **收益**：能够给出正确分母、可复现结果和成本收益。
- **验收**：固定配置/数据哈希、逐案例输出、指标脚本、失败例、重复实验与不确定性；LLM 裁判经人工校准；不给未知费用填 0。
- **面试价值**：这是区分“API 拼接”与“能评价 AI 系统”的关键成果。

### 10. 补齐真实测试层级与工程文档

- **证据/修改位置**：8 个 tsc 错误、50 文件 Mock 测试、唯一 health E2E、CI、README/AGENTS。
- **任务**：修类型错误，独立 tsc 门禁；将现有缺陷观察转成正确行为的回归断言；补真实隔离 PostgreSQL 和核心浏览器旅程；CI 迁移重建；纠正 SQLite/本地隐私/恢复等过时宣称。
- **难度/工作量**：中，2-4 人日，依赖前面修复就绪。
- **收益**：既有绿色测试不再掩盖关键集成缺口。
- **验收**：工程门禁各自报告；Mock 与真实集成分开；health 不作为全流程 E2E；部署步骤能被另一人从空环境执行。
- **面试价值**：可审阅测试设计与真实证据，比单纯增加测试数量更有价值。

建议 P0 优先按 1→2→3→4→5→6，7-10 根据依赖穿插；若准备近期演示，可在完成隔离边界后先修第 4 项保证标准部署。不要为了演示临时隐藏失败状态。

## P2：在 P0/P1 验收后提升

### 11. 接独立模型服务并开展研究实验

`rerank-gateway.ts` 已有适配点。先冻结 BM25/Dense/CE 基线，再做自主训练、蒸馏或轻量化；应用只接版本化 HTTP 契约。难度高，工程接入约 2-4 人日；可信训练/评测通常另需数周，取决于数据标注与算力。验收是固定数据与硬件下的质量-延迟曲线和逐查询误差，而不是“成功返回 scores”。面试价值偏 ML/DL，训练能力需负责人亲自掌握。

### 12. 可观测性与资源优化

围绕现有 Job/usage 补 run/step trace、结构化错误、真实 p50/p95、调用缓存和候选去重；先测量再优化。难度中，2-4 人日；若跨进程部署另估。验收一条任务可串起阶段时延、错误与真实用量，不记录敏感内容。不要在没有负载证据前引入复杂分布式栈。

## P3：暂不实施

新 UI、新角色、新供应商、通用 DAG 平台、微服务拆分和大规模重构。它们不能解决已确认正确性问题，也会增加验证范围。科研论文包装、未经评测的准确率宣称和普通 API 接入冒充训练也不实施。

## 下一轮 Codex 的具体任务边界

建议第一轮只实施 P0-1 与 P0-2：保持接口目的不变，修复 source/FileTool 的读取边界和消息对象归属；先写合成数据回归，使用独立数据库，不访问真实敏感文件。完成类型/lint/相关测试后给出 diff 和结果，再进入 PDF 解析。第二轮 P0-3，第三轮 P0-4/5，第四轮执行状态/恢复，第五轮证据与评测。

每轮都以“触发条件 → 正确行为 → 回归证据”为验收，不按新增代码量或 Agent 数量评估成果。本报告本身不授权立即开始这些修改。
